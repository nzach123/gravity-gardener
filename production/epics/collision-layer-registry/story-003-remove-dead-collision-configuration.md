## Context

**GDD**: `design/gdd/physics-props.md`
**Requirement**: `TR-props-002`
*(Requirement text lives in `docs/architecture/tr-registry.yaml` — read fresh at review time)*

**ADR Governing Implementation**: ADR-0004: Collision layer allocation
**ADR Decision Summary**: Two defects surfaced by the ADR-0004 audit are dead
configuration that reads as intent but has no effect: `PlayerArea2D`
(`player/player.tscn:131`) is an unreferenced child node that nothing signals
through, and `moving_platform.tscn:16`'s `collision_mask = 2` on an
`AnimatableBody2D` is inert because a static/animatable body's own mask is
never evaluated for its own motion (L4). Both should be deleted rather than
re-layered — dead nodes kept "just in case" are how BUG-0001 (story 002)
happened in the first place.

**Engine**: Godot 4.7.1 | **Risk**: LOW
**Engine Notes**: L4 — `godot_body_pair_2d.cpp:256` only reads `collide_A`
when `mode > KINEMATIC`, so `AnimatableBody2D.collision_mask` has no effect on
what the platform pushes or is blocked by — verified against engine source at
the 2026-08-14 specialist gate. This is why `moving_platform.tscn:16` is dead
configuration, not a behaviour to preserve.

**Performance**: No performance impact expected — pure deletion of unused
collision configuration (an unreferenced Area2D node and an inert
collision_mask value). No new runtime checks, physics queries, or per-frame
logic are added or altered.

**Control Manifest Rules (this layer)**:
- Contextual note from ADR-0004 defect audit: a node kept "just in case" on
  the wrong layer is how BUG-0001 happened. Delete, don't re-layer.

> **Corrected 2026-08-23.** This case previously expected `== 0` on the reasoning
> that a removed property leaves the mask empty. That is wrong:
> `CollisionObject2D.collision_mask` defaults to `1`, not `0`, so deleting
> `moving_platform.tscn:16` leaves the body masking `WORLD`. Verified by direct
> probe on Godot 4.7.1 — `AnimatableBody2D.new()` reports `layer=1 mask=1`, as do
> `StaticBody2D`, `Area2D` and `CharacterBody2D`. The expectation is now `== 1`.
>
> The deletion itself is unaffected and still correct. ADR-0004 migration step 5
> says only "delete `moving_platform.tscn:16`, which per L4 does nothing" — it
> never claimed the resulting value would be `0`. Per **L4**, an animatable
> body's own mask is never evaluated for its own motion
> (`godot_body_pair_2d.cpp:256` reads `collide_A` only when `mode > KINEMATIC`),
> so the residual `1` is just as inert as the `2` being removed. Nothing reads as
> deliberate configuration either way, which is the intent the case is testing.
>
> Had this not been caught, story 004's group 5 would have failed against a
> correct implementation of this story.
