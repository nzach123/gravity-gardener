# Bug Report

## Summary
**Title**: Moving platform root node is misspelled `MovingPlatfornm`, breaking the scene-naming convention
**ID**: BUG-0002
**Severity**: S4-Trivial
**Priority**: P3-Backlog (scheduled: Sprint 2)
**Status**: Open
**Reported**: 2026-08-25
**Reporter**: nzach123 (found during Sprint 1 close-out review)

## Classification
- **Category**: Code quality / convention
- **System**: Scene authoring (`moving_platform.tscn` and its four level instances)
- **Frequency**: Always (static authoring defect)
- **Regression**: No. Present since the scene was authored.

## Environment
- **Build**: `f70e965`, branch `vertical-slice`
- **Platform**: PC / Godot 4.7.1-stable, GL Compatibility, 2D
- **Scene/Level**: `moving_platform.tscn`; instanced in levels 02, 04, 07, 08
- **Game State**: Any — no runtime effect

## Reproduction Steps
**Preconditions**: None.

1. Open `src/scenes/moving_platform.tscn`.
2. Read the root node name.

**Expected Result**: The root node is named `MovingPlatform`, matching the scene
filename per the naming convention in `.claude/docs/technical-preferences.md`
("Scenes: PascalCase matching root node").
**Actual Result**: The root node is named `MovingPlatfornm` — `rn` transposed from
`rm`.

## Technical Context
- **Root cause**: A typing slip at authoring time that was never caught, because
  nothing reads the node by name.
- **Affected files** — five lines, all node-name declarations:
  - `src/scenes/moving_platform.tscn:9` (the source root)
  - `src/scenes/levels/level_02.tscn:76` (instance)
  - `src/scenes/levels/level_04.tscn:306` (instance)
  - `src/scenes/levels/level_07.tscn:106` (instance)
  - `src/scenes/levels/level_08.tscn:70` (instance)
- **Blast radius is SMALLER than first assessed.** The initial note said renaming a
  root node "rewrites every referencing node path". Verified false here:
  - No `.gd` file references the name. A repo-wide grep over `*.gd`, `*.tscn` and
    `*.tres` returns only the five node-name lines above.
  - The platform is found by GROUP, not by name — the root declares
    `groups=["platforms"]`.
  - The four level entries are instance node names, which Godot stores
    independently of the source scene's root name. Renaming the source root does
    not by itself invalidate them.
  So the fix is a five-line rename with no code change and no path rewrite. It is
  scheduled to Sprint 2 because it is cosmetic and out of Sprint 1's goal, NOT
  because it is risky.
- **Related systems**: None at runtime.

## Evidence
- **Logs**: None. No runtime effect of any kind — the name is never resolved.
- **Static**: `grep -rn "MovingPlatfornm" --include=*.tscn --include=*.gd --include=*.tres`
  returns exactly the five lines listed above. Verified in the working tree at
  `f70e965` on 2026-08-25.
- **Test impact**: None. `tests/unit/physics/collision_layers_test.gd` reaches this
  scene by path (`MOVING_PLATFORM_SCENE`) and classifies its body by TYPE
  (`body is AnimatableBody2D`), never by node name, so the rename cannot break it.

## Notes
- Purely cosmetic. There is no player-visible symptom and no correctness risk in
  leaving it open.
- When fixing, rename all five sites in one commit. A partial rename leaves the
  source root and its instances disagreeing, which is worse than the current
  consistent misspelling.
