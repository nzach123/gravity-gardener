# Bug Report

## Summary
**Title**: Out-of-bounds kill plane never fires in levels 05 and 06 — player is stranded, not restarted
**ID**: BUG-0001
**Severity**: S2-Major
**Priority**: P2-Next Sprint
**Status**: Open — fix implemented 2026-08-23, awaiting playtest sign-off
**Reported**: 2026-08-14
**Reporter**: nzach123 (found by the ADR-0004 collision layer audit)

## Classification
- **Category**: Gameplay
- **System**: Level lifecycle / restart (`main.gd`), 2D collision configuration
- **Frequency**: Always (100% — the signal is structurally incapable of firing)
- **Regression**: No. Latent since the `KillArea2D` nodes were authored; this
  code path has never executed.

## Environment
- **Build**: `a896cee`, branch `claude-refactor`
- **Platform**: PC / Godot 4.7.1-stable, GL Compatibility, 2D
- **Scene/Level**: `level_05.tscn`, `level_06.tscn` (the only two levels wiring a kill plane)
- **Game State**: Any — no state dependency

## Reproduction Steps
**Preconditions**: Load level 05 or level 06.

1. Move the player to a gap or ledge that leads out of the playable area.
2. Fall past the `KillArea2D` volume (`CollisionShape2D` at local `(-45, 325)`).
3. Continue observing the player.

**Expected Result**: `_on_kill_area_2d_body_entered` fires, sets `player_died = true`,
and `restart_level()` restarts the level.
**Actual Result**: Nothing fires. The player keeps falling forever with the camera
following. The level cannot be completed or exited without a manual restart.

## Technical Context
- **Root cause — confirmed, not suspected**: `KillArea2D` declares neither
  `collision_layer` nor `collision_mask`, so both default to `1` (`world`). The
  player `CharacterBody2D` is on `collision_layer = 2` (`player.tscn:117`).
  `Area2D.body_entered` gates solely on *the area's mask* against *the body's
  layer* (`godot_area_pair_2d.cpp:36`, ADR-0004 L1) — and `1 & 2 == 0`. The area's
  own layer is never consulted, so the signal has no path to fire.
- **Likely affected files**:
  - `src/scenes/levels/level_05.tscn:386` (node), `:400` (connection)
  - `src/scenes/levels/level_06.tscn:392` (node), `:409` (connection)
  - `src/scripts/main.gd:71` — the unreachable handler
  - `src/scenes/player/player.tscn:117` — the layer that does not match
- **Related systems**: Collision layer allocation (ADR-0004), level restart
- **Fix**: Give each `KillArea2D` `collision_layer = 0` and `collision_mask = 2`,
  per ADR-0004 D4.1's detector idiom. Specified as Migration Plan step 3.

## Evidence
- **Logs**: None — the failure is silent by nature. No error is raised; the signal
  simply never emits.
- **Static**: `grep` over both `.tscn` files shows no layer/mask key on either
  `KillArea2D` node. Verified in the working tree at `a896cee`.

## Notes
- **Fixing this changes live behaviour.** Levels 05 and 06 have only ever been
  played with the kill plane dead. After the fix, a fall that currently strands the
  player will restart the level. This is the intended design, but it is a behaviour
  change and **requires a playtest of both levels** (ADR-0004 §Negative consequences).
- Do not fix in isolation: `src/` is deliberately untouched for the whole
  architecture phase. This belongs to the migration epic alongside ADR-0004's other
  four defects.
- Regression coverage arrives with `tests/unit/physics/collision_layers_test.gd`
  (ADR-0004 D4.5), whose assertion 2 catches this class of mismatch.

## Fix Record — 2026-08-23

`KillArea2D` now carries `collision_layer = 0` and `collision_mask = 2` in both
`src/scenes/levels/level_05.tscn` and `src/scenes/levels/level_06.tscn`.

Regression guards in `tests/integration/main/kill_area_death_test.gd` were
confirmed to fail when the mask is reverted to `1`, so they pin the fix rather
than passing vacuously. Full suite: 81/81, exit 0.

**This bug stays Open.** The fix is a live behaviour change — a fall that used
to strand the player now restarts the level — and ADR-0004 Validation Criterion
4 requires human verification of both levels, including a check that neither
level has an in-bounds spot where the kill plane fires unexpectedly. That last
one is a spatial-authoring check no test can make. Close this only after the
playtest is recorded in `production/qa/evidence/`.
