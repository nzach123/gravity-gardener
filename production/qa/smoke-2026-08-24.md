## Negative verification — proof the suite can go red

Each defect was introduced by hand, the suite run, and the change reverted. The
working tree was confirmed clean afterwards.

| # | Defect introduced | Observed | Matches its AC |
|---|---|---|---|
| 1 | `resource_local_to_scene = true` on `prop_tuning.tres` | `test_prop_is_not_local_to_scene` FAILED | Yes |
| 2 | `prop_gravity_scale` changed `1.0` -> `1.15` | `test_prop_defaults_match_gdd` FAILED | Yes |
| 3 | `prop_tuning.tres` re-pointed at `oxygen_tuning.gd` | **Parse error at load**, suite did not run | **No — see below** |
| 4 | `prop_max_speed = "fast"` (wrong type) | `test_prop_defaults_match_gdd` FAILED | Extra check, not in the AC |
| 5 | `prop_tuning.tres` renamed (story 004 manual check) | **Parse error at load**, not a runtime null | Yes |

### Deviation on check 3 — recorded, not resolved

Story 005 predicts that re-pointing a `.tres` at the wrong script fails **group
1** (V1), and that a null check would have passed on the same defect. Neither was
observed. The actual result is:

```
SCRIPT ERROR: Parse Error: Could not resolve external class member "PROP".
ERROR: Failed to load script "res://tests/unit/tuning/tuning_resources_test.gd"
```

Nothing ran at all. The typed constant plus `preload` in `tuning.gd` rejects a
wrong-typed `.tres` **statically**, which is a stronger guarantee than the story
assumed — but it means this route cannot exercise V1, and **V1 has never been
observed failing**.

V1 still earns its place: it guards engine bug GH#73615, where a resource
resolves non-null yet wrong-typed at *runtime*, which is a different vector from
an author mis-editing a `.tres`. That vector was not reproduced here. Do not read
this smoke check as evidence that V1 works — only that it does not misfire.

### Note on the carried silent-zero finding

Check 4 tested the failure mode the T4 spike found outside its scope: a
wrong-TYPE value in a `.tres` resolves at runtime as `0.0` rather than as the
declared default, silently. The value assertion catches it on its own, so the
`typeof()` assertions added to group 4 are redundant for *this* vector. They were
kept because they still cover the int/float truncation case, which a value
assertion would miss when the truncated result happens to equal the default.
